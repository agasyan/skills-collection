# Write for a global audience
Google (last updated 2026-10-02). Google developer documentation style guide. https://developers.google.com/style/translation
Type: blog · Read: 2026-10-06

## Core idea
Many readers translate the docs or read English as a second language, so write short, plain, literal, consistent sentences that survive translation.
Evidence: none cited

## Points
- **Simple words.** Write start, not commence; use, not utilize or leverage; some or many, not a number of.
- **Shorter sentences.** The shorter the sentence, the easier it is to translate; long sentences impair understanding and raise translation cost.
- **Active voice, present tense.** With passive voice, readers struggle to tell who is supposed to do something.
- **Address the reader as you.** Write you, not the user or they, and don't assume the reader already knows the context.
- **Condition first.** State the circumstance before the instruction, and keep subject and verb near the start of the sentence.
- **One term per concept.** Different names for the same thing make translators think they are different concepts.
- **Keep helper words.** Keep that, then, and of, and repeat a word when the repetition improves comprehension.
- **Precise, not subjective.** Drop simply, properly, and carefully; spell out abbreviations at least on first use.
- **No idioms or humor.** Phrases like ballpark figure or back burner, and most humor, are hard to translate and culturally specific.

## For writing docs
- Write "If X, then do Y", not "Do Y if X".
- Pick one name per concept and use it everywhere, with the same capitalization.
- Replace "X is required" with "You must X", naming who acts.
- Spell out each abbreviation the first time it appears.
