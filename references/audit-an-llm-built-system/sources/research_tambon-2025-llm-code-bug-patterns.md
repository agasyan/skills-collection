# Bugs in Large Language Models Generated Code: An Empirical Study
Florian Tambon, Arghavan Moradi Dakhel, Amin Nikanjam, Foutse Khomh, Michel C. Desmarais, Giuliano Antoniol (2025). Empirical Software Engineering 30(3). https://arxiv.org/abs/2403.08937
Type: research · Read: 2026-10-06

## What it says
- Hand-labeled 333 failing samples (from 1,997) generated by CodeGen, PanGu-Coder, and Codex on CoderEval: 230 Python functions from 43 real open-source projects.
- Built a 10-pattern bug taxonomy and validated it with a survey of 34 practitioners and researchers.

## Findings
- **Misreading the task is most common.** Misinterpretation, code that deviates from the prompt's intent, was 20.77% of bugs.
- **Missed edge cases.** Missing Corner Case was 15.27% overall and 23.53% for Codex.
- **Unrequested additions.** Non-Prompted Consideration, code that adds conditions or steps nobody asked for (e.g. sorting output the spec never mentioned), was 8.15%; Codex, the strongest model, did it most (11.76%).
- **Looks right, isn't.** The authors note such code seems correct "at first glance," and adding a non-prompted feature is "something that a human developer would rarely do."
- **Invented APIs.** Hallucinated Object (calling things that do not exist) was 9.57%; Wrong Attribute 8.55%.
- **Overfitting to examples.** Prompt-biased code (6.52%) works only for the example given in the prompt.
- **Practitioners agree.** Respondents had met all 10 patterns; Wrong Attribute, Prompt-biased Code, and Missing Corner Case were encountered most.

## For auditing an LLM-built system
- Trace every branch, transformation, and filter to a stated requirement; one with no source is a Non-Prompted Consideration.
- Compare behavior with what staff asked for in their own words, not with what the code's comments claim.
- Test boundary and exception cases first; missing corner cases were the top bug for the strongest model.
- Confirm every external call and attribute exists in the pinned library version.
